# ADR 0003 — Driver qBittorrent et exécution des commandes (phase 3)

1. **Trait `TorrentClient`** (agent, `async_trait` pour `dyn`) : `list/add/pause/resume/recheck/remove/set_limits/disk_free/version` + `kind()`. Les infohash y arrivent déjà normalisés (40 hex minuscules). Le statut est mappé vers l'enum stable `proto::TorrentStatus`.
2. **L'agent ne croit pas le master** : `Executor` revalide chaque commande localement (infohash, magnet, chemin). Un magnet doit commencer par `magnet:?`, contenir un `btih` valide, sans espace/contrôle, ≤ 4 Ko. Aucune URL `http(s)`/`file` n'est acceptée comme source.
3. **Chemins** (`paths::resolve_under`) : relatif obligatoire ; rejet de `/`, `\`, `..`, `:`, contrôles ; chaque composant existant est canonicalisé et son préfixe revérifié (symlink sortant, lien pendant → refus). Le chemin absolu n'est jamais renvoyé au master : `TorrentInfo.save_subdir` est recalculé relativement à la racine.
4. **Idempotence** : clé = infohash. `Add` déjà présent → succès sans effet ; `Pause/Resume/Remove` rejouables.
5. **API qBittorrent** : `reqwest` sans fonctionnalité TLS côté agent (HTTP local), cookie `SID`, ré-authentification automatique sur 403 (une seule tentative). L'URL doit être **loopback** (`127.0.0.1`, `::1`, `localhost`), sinon le client refuse de se construire. Compatibilité v4/v5 : `pause`→`stop` et `resume`→`start` sur 404 ; `paused` et `stopped` envoyés à l'ajout. Le mot de passe passe par variable d'environnement (`AGENT_QBIT_PASSWORD`), jamais en argument ni dans `Debug`/logs ; les URL sont retirées des messages d'erreur.
6. **Événements** : déduits par différence d'instantanés (`list` toutes les 5 s) : `Added`, `Removed`, `Completed` (progression passant à ≥ 0,9999). `event_id` aléatoire 128 bits. Le master dédoublonne par `event_id` (fenêtre de 1000). Conséquence connue : une complétion survenue pendant une coupure n'est pas détectée à la reconnexion (la ligne de base est le `FullState`) ; la persistance/rejeu des événements non acquittés arrive en phase 4.
7. **Master** : l'état observé (torrents, disque, événements, acks, stats) est conservé en mémoire par nœud (`NodeTelemetry`), distinct de l'état désiré. Un `Ack` négatif est audité (`command_refused`). `Core::send_command` n'atteint que les nœuds avec tunnel actif ; la file de commandes hors ligne = réconciliation (phase 4).
8. **Webhook** : POST JSON `{event: node_online|node_offline, node_id, timestamp}`, timeout 10 s, pas de redirection, URL jamais loggée (peut contenir un secret). `reqwest` + `rustls-tls` (ring, pas d'aws-lc) côté master seulement.
9. **`testkit`** (crate de dev, non livré) : faux qBittorrent et récepteur de webhook (axum). Un test `#[ignore]` vise une vraie instance (`QBIT_URL/QBIT_USER/QBIT_PASS`).

## Bug trouvé par les tests et corrigé
Un nœud fraîchement appairé est déjà `Online` en base : sa première connexion ne changeait pas l'état et ne planifiait donc aucune confirmation de présence, ce qui rendait sa première coupure silencieuse. Toute connexion planifie désormais une confirmation (sans notification si l'état notifié est déjà correct).
