# ADR 0007 — Support de Windows / Windows Server

Cibles : `x86_64-pc-windows-msvc` (et `aarch64`), en plus de Linux (musl). Master et agent compilent et passent toute la suite sous Windows ; les points ci-dessous traitent ce qui ne se traduisait pas tel quel.

1. **Secrets** : le `0600` n'existe pas. `fsutil::write_secret` applique une ACL via `icacls` AVANT d'écrire le secret : héritage coupé, accès complet à SYSTEM (`*S-1-5-18`), Administrateurs (`*S-1-5-32-544`) et l'utilisateur courant. SID bien connus -> indépendant de la langue de Windows. Échec = erreur (jamais de clé laissée lisible). Repli sans le compte courant si celui-ci ne se résout pas (service, domaine injoignable). Passer par `icacls` (livré avec Windows) garde le code sans `unsafe`. Test : `secret_acl_excludes_other_accounts_on_windows` (aucun Everyone/Users/Authenticated Users, aucun droit hérité).
2. **Chemins** : `canonicalize` renvoie `\\?\C:\…` sous Windows, que les clients torrent ne comprennent pas. `paths::simplify` retire ce préfixe (les chemins UNC sont conservés) ; la validation anti-évasion (symlinks/jonctions) compare des chemins simplifiés des deux côtés. `relative_to` normalise séparateurs, préfixe verbatim et casse (Windows insensible à la casse).
3. **Binaire autonome** : `.cargo/config.toml` lie le runtime C statiquement (`+crt-static`) ; vérifié : aucune dépendance à VCRUNTIME140/MSVCP140/api-ms-win-crt dans `master.exe` et `agent.exe`. Rien à installer sur Windows Server.
4. **Clients** : qBittorrent, Transmission et Deluge existent sous Windows ; rTorrent/ruTorrent non (le driver reste utilisable contre une instance Unix locale, mais refuse par conception les chemins à antislash).
5. **Service Windows natif** (`agent service …`, `master service …`) via la crate `windows-service`, isolée dans le crate `winsvc`. Les crates applicatives restent `forbid(unsafe_code)` ; seul le point d'entrée FFI imposé par le gestionnaire de services (macro `define_windows_service!`) est `unsafe`, confiné au module `winsvc::imp` (`#![allow(unsafe_code)]` local, crate en `deny`). C'est la justification explicite de l'exception à la règle « pas d'`unsafe` ».
   - Installation : démarrage automatique **différé**, compte LocalSystem, redémarrage automatique après plantage (5 s, 30 s, 60 s, remise à zéro après 24 h).
   - Arrêt : le SCM (Stop) ou l'extinction de Windows déclenche un `Notify` ; l'agent/le master s'arrête proprement (état StopPending pendant l'arrêt, puis Stopped avec code de sortie).
   - **Aucun secret dans la configuration du service** (`ImagePath` est lisible par les comptes locaux) : le mot de passe du client torrent (`client_password`) et l'URL de webhook (`webhook_url`) sont écrits dans des fichiers à ACL restreinte et relus au démarrage (`fsutil::read_secret` : variable d'environnement d'abord, fichier sinon). Les chemins passés au service sont absolus (le SCM démarre dans System32).
   - Sans console : journaux dans `agent.log` / `master.log` du répertoire de données (rotation à 10 Mo, une génération `.old`).
   - `agent service install` exige un agent déjà appairé et un dossier de téléchargement existant ; `service run` lancé depuis une console renvoie une erreur explicite.
6. **CI** : job `windows-latest` (tests + build release + artefacts `.exe`).

## Limites
- Les droits NTFS dépendent de `icacls` : sur un Windows très restreint (AppLocker interdisant `icacls.exe`), l'écriture des secrets échoue franchement plutôt que de s'effectuer sans protection.
- **Vérifié sur Windows 11 (terminal Administrateur)** : cycle de vie réel du master (install, start, listener, stop propre, uninstall), redémarrage automatique après un plantage simulé (`taskkill /F`, nouveau PID, et un arrêt volontaire n'est PAS relancé), et cycle de vie de l'agent de bout en bout (appairage, service qui tient le tunnel, mot de passe du client lu dans le fichier protégé, commande jusqu'au client, plantage puis rétablissement du tunnel). Tests : `master/tests/windows_service.rs` et `agent/tests/windows_service.rs` (`--ignored`), aussi exécutés par la CI Windows.
- Non testé ici : Windows Server proprement dit (testé sur Windows 11) et Windows sur ARM.
